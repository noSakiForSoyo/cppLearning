## 二、⭐ 最大的一个坑：librknnrt 版本不匹配

### 症状

```
E RKNN: 6, 1
E RKNN: Invalid RKNN model version 6
E RKNN: rknn_init, load model failed!
!! rknn_init failed ret=-1
```

### 原因

| | 版本 |
|---|---|
| 板子出厂 `librknnrt.so` | **1.4.0（2022-09-09）** |
| rknn-toolkit2 2.3.2 产出的模型 | **model version 6**（模型头 `52 4b 4e 4e` + `06 00 00 00`） |

**version 6 需要 runtime ≥ 2.x。**

### 解决

```bash
# 备份（已经做了，备份文件还在）
cp -a /usr/lib/librknnrt.so /usr/lib/librknnrt.so.bak-1.4.0

# 换成 2.5.0（aarch64），位置：
#   WSL: ~/projects/rknn/cpp/rknn_lib/librknnrt.so
scp librknnrt.so root@192.168.137.100:/usr/lib/
ldconfig
```

**升级后：**
```
sdk: api=2.5.0 (74ea630ce8@2026-09-30T09:41:17) drv=0.9.8
rknn_init OK
```

**⇒ 升级了 runtime 但【没升级内核驱动】，也能跑。**

### 回滚（如果需要）

```bash
ssh root@192.168.137.100 \
  'cp -a /usr/lib/librknnrt.so.bak-1.4.0 /usr/lib/librknnrt.so && ldconfig'
```

## 四、⭐⭐ 重要发现：仿真器 ≠ 真机

**同一个模型、同一张图（letterbox 后的 640×640）、同一套后处理：**

| 类别 | Python 模拟器 | **板子真实 NPU** |
|---|---|---|
| cup | 0.750 `(431.6,222.8,476.5,287.3)` | **0.750 `(440.0,225.6,484.9,290.1)`** |
| cup | 0.273 `(319.5,203.2,370.0,267.7)` | ❌ **掉了（分数跌到 <0.25）** |
| cell phone | 0.259 `(406.4,420.4,423.2,431.6)` | **0.279 `(405.0,420.4,424.6,431.6)`** |
| book | 0.438 `(351.7,222.8,427.4,298.5)` | **0.420 `(354.5,222.8,430.2,298.5)`** |

**解读：**
- `scores max` 完全一致：**0.749637** vs `0.7496365` ✅
- 坐标差异是 **整数个量化格**（`8.4 = 3 × 2.802722`）
- **阈值附近的框（0.273）在真机上会掉出去**

> **➡️ P3 那张精度对比表，必须补一列「板上实测」。**
> **这一列是只跑模拟器的人拿不出来的。**

## 五、Baseline 数字（真机实测）

| 阶段 | 耗时 |
|---|---|
| 读图（PPM） | 1.88 ms |
| **NPU 推理** | **81.89 ms** |
| **`outputs_get`（`want_float=1` 反量化 67 万个 float）** | **7.74 ms** |
| **后处理（decode + NMS）** | **10.80 ms** |
| **合计** | **≈ 102 ms → 约 10 FPS** |

### 两个立刻能优化的点

| 点 | 现在 | 优化思路 |
|---|---|---|
| `outputs_get` 7.74 ms | `want_float=1` 全张量转 float | ⭐ 改 `want_float=0`，只反量化通过阈值的几十个（官方做法） |
| 后处理 10.80 ms | 全扫 8400×80 = 67 万次 | ⭐ 阈值先量化成 int8，全程整数比较 |

**加起来 ≈ 15 ms，占 15%。**
